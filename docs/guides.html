Physics: bake a scene, read poses

A Stage is one planck.js (Box2D) world. You add actors, bake it once in fixed steps (240 Hz by default) and it stores one pose per frame for every actor. After that, reading a pose is a pure function of the frame, so it doesn't matter in which order, or how often, frames are drawn.

import { Stage, Body, SpringyBody, LAYER, poseAt } from "romp/core";

const s = new Stage();                       // px; y down; gravity a little heavier than life
s.ground([{ x: 10, y: 0 }, { x: 10, y: 470 }, { x: 790, y: 470 }, { x: 790, y: 0 }]);

// A shelf only the letters (layer B) and the flung character (layer C) touch.
const shelf = s.ground([{ x: 250, y: 205 }, { x: 550, y: 205 }], { layer: LAYER.B });
s.add(new SpringyBody({ id: "p", x: 497, y: -30, w: 64, h: 84, spawn: 22, ground: shelf, groundY: 205,
                        layer: LAYER.B, mask: LAYER.B | LAYER.C }));
s.add(new Body({ id: "zip", shape: "circle", x: 880, y: 175, w: 70, h: 70, spawn: 40, vx: -1500,
                 layer: LAYER.C, mask: LAYER.FLOOR | LAYER.B | LAYER.A | LAYER.C }));
s.add(new Body({ id: "ada", x: 120, y: -30, w: 96, h: 86, spawn: 92, vy: 800, upright: true,
                 layer: LAYER.A, mask: LAYER.FLOOR | LAYER.A | LAYER.C }));  // skips the shelf
s.bake({ frames: 225, fps: 30 });

const p = poseAt(s.get<Body>("ada"), frame);   // { shown, x, y, angle } (centre, px)
  • Units: metres in the world and px on screen (pxPerMetre, default 100). new Stage({ yDown: false }) for y-up scenes such as three.js.
  • Bodies take their feet position, size, shape ("rounded", "box" or "circle"), a spawn frame, a launch velocity and spin, restitution, upright, and a collision layer and mask.
  • Impacts are recorded as the world bakes: a sudden loss of speed in the gravity direction, with its frame, time and speed. body.landed is the first one.
  • SpringyBody welds itself to its ground where it first lands on that ground (a knock in mid-air doesn't weld it), so it can be knocked over and wobble back.
  • Drop is a dropped prop that stays upright: a contact foot, a gravityScale (small props fall snappier), spinAt and tilt that unwind to zero exactly at touchdown, depth drift z: [from, to] arrested on contact, a rock direction, and its own ledge with a frame offset to draw it in its parent's coordinates (flight(frame), framePose(frame)). Leap is a ballistic leap through a surface (a fish), with a gravity scale and frame offset, recording where it crosses it.
  • Your own actors implement build(stage), control(t, dt), sample(t) and, optionally, apply(pose, t); stage.add() sets actor.stage first, and stage.pose(t) hands every actor its interpolated pose (a pose with a NaN in it arrives as { shown: false }). baked(key, build) memoises a stage per scene.
  • Matching an existing renderer: booleans and strings switch at the halfway point between baked frames; poseAt(actor, frame, { discrete: "previous" }) holds the earlier frame's value instead.
  • Spawn actors off screen (above the frame, say) so the motion check never sees one pop into place.

Motion: reactions from real impacts

impactResponse(body, frame) turns a body's recorded impacts into a character's reaction, each sized by how hard it hit and decaying on its own curve. For characters that land against each other in a pile, pass a style that keeps the squash from spreading past the body into a neighbour, e.g. impactResponse(body, frame, seed, 900, { squash: 0.15, widen: 0.2 }). Draw each character the same shape as its body (a round body drawn round) and rotate the drawing about the body's centre, not its feet, so what you see is what collides:

import { impactResponse, jiggleParts } from "romp/core";

const look = impactResponse(body, frame, seed);
// squashX / squashY: squash about the feet on landing, stretch while falling fast
// tilt / lift:        the hat (or antenna) lags and settles: follow-through
// blink:              eyes shut on a hard impact, plus unsynced idle blinks
// jiggle:             a single secondary-motion value

// Several parts that follow through in turn (brim, then crown, then pom-pom):
const last = body.impacts.filter((h) => h.frame <= frame).at(-1);
const parts = last ? jiggleParts(["brim", "crown", "pom"], frame - last.frame, last.speed / 900) : {};

Without physics, the same vocabulary is available as pure functions of the frame: landing(frame, land) (a scripted landing), hop(frame, period, height) (a hop cycle with squash on contact), idle(frame) (breathing and blinks), blinkAt(frame, seed), boing(dt) (a decaying oscillation) and rock(impacts, frame) (a rigid prop rocking about its contact point). ease, spring(), ringOut() and stagger() are closed-form curves for everything that isn't simulated. Use a spring or ease.out for entrances, never a straight line.

Two ways to play: live or frame by frame

Write one seek(t) that draws film time t. Both modes call it.

Live (a viewer page)

The Clock drives seek(t) from requestAnimationFrame. While sound is playing, the picture follows the audio clock (AudioContext.currentTime), so the two can't drift; otherwise it follows performance.now(). playLive plays the soundtrack from any point: scrub to 3.2 s and press play, and everything scheduled before 3.2 s is skipped.

import { Clock } from "romp/core";
import { playLive } from "romp/audio";
import { cartoon } from "romp/audio/cartoon";

const audio = new AudioContext();
let live;
const clock = new Clock({
  seek, duration: 7.5, loop: true, audio,
  onPlay: async (t) => { live = await playLive(audio, schedule, { from: t, extend: cartoon }); },
  onStop: () => live?.stop(),
});
playButton.onclick = () => (clock.playing ? clock.pause() : clock.play());
scrubber.oninput = () => clock.seek(+scrubber.value);   // restarts the sound there if playing

Frame by frame (Remotion, or a page captured to MP4)

Read poses by frame and render the same schedule offline:

// in a Remotion component
const pose = poseAt(body, useCurrentFrame());

// the soundtrack, offline (deterministic: same schedule, same samples)
import { renderOffline, renderWav } from "romp/audio";
const buffer = await renderOffline(schedule, { duration: 7.5, extend: cartoon });
export const render = () => renderWav(schedule, { duration: 7.5, extend: cartoon });   // for `romp sound`

Sound: one schedule

A soundtrack is a function that schedules every note and cue in film seconds through at(t). Live, at maps film time to the context's time and returns null for anything already played; offline it's the identity.

import { Instruments, type Schedule } from "romp/audio";

export const schedule: Schedule = (s, bus, at) => {
  const band = new Instruments(s);          // pluck, kick, shaker, rhodes, piano, upright, rim, brush
  for (let b = 0; b < 16; b++) {
    const t = at(b * 60 / 112); if (t == null) continue;
    if (b % 2 === 0) band.kick(t, bus.drums, { vel: 0.22 });
    band.shaker(t, bus.drums, { vel: 0.03, seed: b });
  }
  for (const hit of body.impacts) {          // the same impacts the picture reacts to
    const t = at(hit.t); if (t == null) continue;
    s.boing(t - 1 / 30, bus.sfx, { k: hit.speed / 900, big: size / 95 });   // a frame early
  }
};
  • The mix (createMix) has music, drums, sfx and voice buses with a shared room, a 70 Hz high-pass, a low shelf and a glue compressor.
  • The voices (Synth): marimba, bell, Karplus–Strong plucks, whooshes, taps, splashes, risers, thumps and more, all synthesised. romp/audio/cartoon adds plop, boing, babble (gibberish voices: hero, squeaky, low, sleepy, playful, … or your own { f0, swing, rate }), slurp, beep, ding, tock, pip, swish and scribble.
  • In key: set s.harmony = (t) => pitchClassSet and every tonal effect snaps to the chord sounding at that moment (fitTo).

The rules worth keeping: restraint (only each beat's focal event gets a sound), one family (tonal effects on one voice, in the score's key), transients lead the picture by about a frame (LEAD), no identical repeats (every voice takes a seed), and keep the energy between 200 Hz and 6 kHz so it survives a phone speaker. romp sound normalises the result to −16 LUFS.

Sound as a signal

Visuals that react to the soundtrack usually read a live analyser, which a frame-by-frame renderer can't have. romp's soundtrack is already a schedule, so it can tell you what plays when. listen(schedule) runs the schedule once against a silent stand-in for an AudioContext and records every voice it calls: when, on which bus, how loud, which note and how long it rings. The Score it returns answers as pure functions of film time:

import { listen } from "romp/audio";
import { cartoon } from "romp/audio/cartoon";

const score = listen(schedule, { extend: cartoon });    // once, next to your baked stage

function seek(t) {
  const kick = score.envelopeAt(t, { voice: "kick", decay: 0.25 });   // a pulse on every kick
  shelf.style.opacity = String(0.7 + 0.3 * Math.min(1, kick / 0.22));
  const { phase } = score.beatAt(t);                                  // 0 → 1 between drum onsets
  logo.style.scale = String(1 + 0.04 * Math.exp(-phase * 6));
  for (const hit of score.onsetsBetween(t - 1 / 30, t, { bus: "sfx" })) flash(hit.voice);
}
  • What's recorded: the outermost voice call only (an upright plucks inside, a ding plays a marimba: one event each), with its bus (found through any panner or filter on the way), its vel or the voice's default, and its note for tonal voices.
  • Shapes: a hit attacks in 5 ms and decays over its voice's ring (decay overrides it: short for a snappy pulse); a swell (whoosh, riser, engine) rises to its peak and falls; a bed (crackle, surf, babble) holds.
  • Times are as scheduled, so a transient you led by a frame (LEAD) peaks a frame before the picture's impact, as it should.
  • The schedule must be synchronous. The demo above brightens its shelf on every kick this way.

Particles

Real-time particle libraries step a simulation every animation frame, so a renderer that draws frame 90 before frame 89 (Remotion does) gets a different burst each time. romp/particles makes every particle a pure function of the frame: its launch (where, which way, how fast, its size, colour and spin) comes from a seeded hash of its own index, and its flight is closed-form (gravity, wind, linear drag, a sideways sway, spin and a confetti flip).

import { Emitter, confetti, sparks, snow, particlesAt, particleStyle, drawParticles } from "romp/particles";

const burst = new Emitter(confetti({ x: 540, y: 900, at: 45, seed: 3, ground: 1830 }));
const hits = new Emitter(sparks({ x: hit.x, y: hit.y, at: hitFrame, direction: -Math.PI / 2, spread: 2.4,
                                  ground: [[{ x: 250, y: 205 }, { x: 550, y: 205 }], 470] }));
const flakes = new Emitter(snow({ width: 1080, height: 1920, until: 900 }));

// Remotion / DOM: one element per particle, keyed by its stable index
burst.particlesAt(frame).map((p) => <i key={p.i} style={particleStyle(p)} />);
// canvas
drawParticles(ctx, particlesAt([burst, hits, flakes], frame));
  • Plain data out: { i, x, y, x0, y0, vx, vy, angle, size, length, flip, opacity, color, shape, age, life, resting }, so DOM, SVG, canvas and three.js renderers can all draw it.
  • Grounds: a y, or the same polyline you gave stage.ground(), or a list of them. Particles bounce (bounce, friction) and come to rest on floors; bounces are found once per particle by stepping the same closed form at 240 Hz.
  • Streams: rate particles per second, for count particles or until the frame until. Changing count never reshuffles the particles you already had.
  • Presets are options to spread and override: confetti (tumbling paper), sparks (streaks that face their motion: align, stretch), snow (a stream from above the frame, swaying) and fountain.

Particles and the motion check

Particles grow in (grow, 0.08 s) and fade out (fadeOut, 0.3 s) by default, so even tracked one by one they aren't pops; set both to 0 and the check will catch them. But single sparks fly faster than the strobe limit by design, so track the burst as one object instead: trackBurst(name, particles) from romp/remotion gives an empty element covering the burst, centred where it comes from, at its strongest opacity; particleSample(particles) gives the same sample for your own collector. A burst spreading out is a change of size, not a move. Particle elements you don't mark aren't checked at all. A burst that fills the frame may need allowCrop.

const sparks = hits.particlesAt(frame);
<div {...trackBurst("sparks", sparks)} />
{sparks.map((p) => <i key={p.i} style={particleStyle(p)} />)}

The motion check

It steps every frame, follows each tracked element's on-screen centre, box, size and opacity, and flags:

IssueWhat it means
popAppears or vanishes in frame at 30% or more of its largest size, and opaque. It should grow, fade or fly in.
strobeMoves more than about 100 px in one frame (scaled from an 886 px-wide frame). At 30 fps that reads as a jump.
teleportJumps more than about 300 px while visible on both frames.
spikeAcceleration jumps far above its neighbours': a kink where two moves don't match speed.
croppedShown and on screen, but more than 25% of its own box is outside the frame for more than 0.5 s in a row: a character's head cut off by the edge. Entering or leaving (its on-frame share only rises, or only falls) is fine. Tune with croppedFraction and croppedSeconds.
lostHas been in frame, then leaves it entirely (still shown) and stays out for more than 1 s: it bounced off the stage, fell out of the picture or wandered off. An entrance from off-frame is fine, and so is an object a moving camera leaves behind (three.js: where it last was in view is out of view too, so the camera moved on). Mark a real exit with allowExit; tune with lostSeconds.

Exempt: real impacts (an element marked as at an impact, or impacts frames you pass), deliberate fast moves (whips, in seconds), frames where a transition covers the picture (covered), entrances and exits that fade, grow or shrink, seamless objects that swap in for an identical twin, and allowCrop objects that may run off the edge (track(name, { allowCrop: true }), data-romp-allow-crop, userData.allowCrop in three.js). The cropped check needs the frame's width and height; romp check and motionReport pass both.

Remotion or any DOM page

import { track } from "romp/remotion";
import { nearImpact } from "romp/core";

<div {...track("hero", { impact: nearImpact(hero.impacts, frame) })} style={…} />
// check.tsx: the composition to check (or a function of --arg)
export default (lang) => ({ component: MyVideo, props: { lang }, durationInFrames: 1527, fps: 30,
  width: 1080, height: 1920, covered: [[4.2, 4.9]] });
bunx romp check check.tsx --public public --arg '"en"'   # exit 1 on issues; --json for machines

On a page of your own, step your seek(t), collect each frame with collectDom(root) and call analyze(frames, { fps, width, height }): the demo on the home page does exactly that.

three.js

import { motionReport } from "romp/three";
const { issues } = motionReport({ seek, scene, camera, fps: 30, W: 886, H: 1920, from: 0, to: 30, whips, covered });

Name the objects worth checking (obj.name = "van"); deliberate landings go in obj.userData.impacts (seconds), swapped twins set userData.seamless.

The CLI

romp check <entry.tsx> [--public dir] [--from s] [--to s] [--arg json] [--strict] [--audio file.wav] [--json]
romp check --audio <file.wav> [--json]
romp check --lottie <anim.json> [--layers a,b] [--from s] [--to s] [--json]
romp sound <module.ts> --out file.wav [--arg json] [--lufs -16]

romp check bundles the entry with esbuild, plays it in headless Chromium with @remotion/player and seeks every frame. It exits 1 on any issue, motion, text or audio; --strict counts untagged objects as props for the overlap rule and runs the stale rule. romp sound bundles a module exporting render(arg) (an AudioBuffer or a base64 WAV), renders it in headless Chromium and loudness-normalises it with ffmpeg when it's on your PATH.

Text on screen: the text rules and timing

Captions typed into speech bubbles, headings over footage, a ring round the button being described: the check can't tell these from props unless you say what they are. Give a tracked object a role (text, focus or prop) and, for text, its words and how many characters are showing, and these rules run as well. They're on by default for anything with a role, so a film that tags nothing sees no change.

IssueWhat it means
offsafeA legible text's box isn't inside the safe area for more than 0.1 s. By default the long side keeps 5% at each end (a phone's notch, rounded corners and status bar) and the short side 3.5% at each edge: 38 px left and right and 96 px top and bottom at 1080×1920, the other way round at 1920×1080. Words must never touch the edge, unlike cropped's 25% for props. Sliding in or out is fine. safe takes a share of each side, or margins in px.
coversA text sits over the focus box, the highlighted thing it's talking about, for more than 0.1 s: a bubble covering the very button it describes.
overlapTwo texts overlap, or a prop is drawn over a text (papers piling over a title, dots falling through it) for more than 0.2 s. A prop drawn under the text (a lower z; the DOM collector uses document order) is a backdrop.
unfinishedA text disappears, or its scene cuts, before every character is shown: a caption cut off mid-word. Scene starts (scenes, seconds) and the start of every covered transition are cuts.
unreadA text is whole for less than its reading time before it goes. readingTime(text): 180 words a minute, never under 1.5 s; tune with reading: { wpm, min }.
emptyA bubble or heading box is visible with no words for more than 0.2 s, or a heading is still typing 0.5 s after it appears: the blank title between scenes. A heading should arrive whole with its scene.
staleWith --strict or stale: true: nothing tracked changes for more than 3 s after every text on screen was read.

Each rule's thresholds are options (offsafeSeconds, coversFraction, coversSeconds, overlapFraction, overlapSeconds, emptySeconds, headingSeconds, reading, stale), and each has an allow-list: allow: { offsafe: ["credits"], covers: ["caption:*"] } (a trailing * matches a prefix), or allow on the object.

Timing that passes by construction

captionTiming(text, { cps: 30 }) types a caption at 30 characters a second, then holds it whole for its reading time: { typeFrames, holdFrames, totalFrames, typed(frame) }. timeline(scenes, { transition: 0.5, actSeconds: 1.2 }) lays out a film from its scenes: each lasts at least as long as its captions need, the transitions at both ends are added on, so a transition never lands on a caption's reading window, and an act card is 1.2 s unless you say otherwise. It hands back the covered spans and scene cuts the check wants.

import { captionTiming, timeline, trackText, track, sceneSequence } from "romp/remotion";

export const film = timeline([
  { name: "intro", seconds: 4 },
  { name: "act-one", act: true },
  { name: "confirm", captions: ["Is this yours?", "One tap and it's on your phone"] },
], { fps: 30, transition: 0.5 });

const t = captionTiming(text);
const typed = t.typed(frame - from);
<div {...trackText(`bubble:${from}`, text, { typed })}>{text.slice(0, typed)}</div>
<div {...track("ring", { role: "focus" })} />                     // what the bubble must not cover
<h1 {...trackText("title", heading, { heading: true })}>{heading}</h1>

// check.tsx
export default { component: Film, durationInFrames: film.frames, fps: 30, width: 1080, height: 1920, ...film.check };

On a DOM page of your own, the attributes are data-romp-role, data-romp-text, data-romp-chars-shown, data-romp-chars-total, data-romp-heading, data-romp-allow and data-romp-z; without the character attributes, the collector reads the element's own text as all shown. Anywhere else, put role, text and chars: { shown, total } on the sample. The demo on the home page has a caption tracked this way: tick “Plant a text bug” and it's cut off mid-word.

The soundtrack: dropouts and one bed

A music bed that drops to near silence for a moment and comes back reads as a glitch, usually where separately written pieces were joined with a gap. romp check --audio mix.wav, or dropouts(buffer) from romp/audio, flags runs of 0.1–1 s at least 30 dB under the bed's typical level with sound on both sides. Silence at the ends, and longer rests, are left alone.

bunx romp check --audio public/sound/mix.wav            # the audio alone
bunx romp check check.tsx --audio public/sound/mix.wav  # both; either fails the command

To write one continuous bed across scene joins, give each section of the score its span and a writer: crossfadeBed stretches each section's end to the next one's start, writes each a little past its joins, and crossfades them with an equal-power curve.

import { crossfadeBed } from "romp/audio";
crossfadeBed(s, bus.music, [
  { from: 0, to: 12.4, write: (out, t0, t1) => groove(s, out, t0, t1) },
  { from: 12.4, to: 40, write: (out, t0, t1) => pads(s, out, t0, t1) },
], { fade: 0.6 });

Other timelines: Lottie, Theatre.js, Motion Canvas

Anything you can seek can host romp's baked motion and be checked. These adapters are thin: none of them imports its library (each is an optional peer dependency), so they load anywhere and you pass in what they need.

Lottie (After Effects exports)

romp/lottie steps a lottie-web animation with goToAndStop(frame, true) and reads every layer as lottie-web computed it: its transform through its parents and any precomps it sits in, its opacity, and its in and out points. A layer that cuts in at full size is a pop, a hold keyframe that jumps it across the comp is a teleport, one parked half off the comp is cropped. Motion designers can run it on an export before it ships.

import lottie from "lottie-web";
import { lottieReport, formatReport } from "romp/lottie";

const anim = lottie.loadAnimation({ container, renderer: "svg", autoplay: false, loop: false, animationData });
const report = lottieReport(anim, { allowCrop: ["background"] });   // every layer; or { layers: ["ball", "badge"] }
console.log(formatReport(report, anim.frameRate));
bunx romp check --lottie anim.json             # headless Chromium; exit 1 on issues (needs lottie-web installed)

Layers are named by their After Effects name, precomp layers as "Precomp/Layer". Null and matte layers aren't tracked. Boxes come from solids, images, precomps, shape paths (vertices and handles, through each group's transform) and, in a browser, text.

Theatre.js

A Theatre sequence's position is film seconds. Let Theatre's playhead drive romp (the studio's scrubber, sequence.play()), or let romp drive Theatre (the Clock, a Remotion frame, the motion check):

import { onChange } from "@theatre/core";
import { followSequence, seekSequence, theatreReport, objectsRow } from "romp/theatre";

const stop = followSequence(sheet.sequence, onChange, (t) => stage.pose(t));
const clock = new Clock({ seek: seekSequence(sheet.sequence, (t) => stage.pose(t)), duration: 6 });

const report = theatreReport({ sequence: sheet.sequence, to: 6, fps: 30, width: 1920, height: 1080,
  collect: () => objectsRow({ hero, badge }, { size: { w: 120, h: 120 }, frame: { width: 1920, height: 1080 } }) });

objectsRow reads each object's x, y, opacity, scale, width, height and visible; or collect with collectDom(root). If your objects update on Theatre's rafDriver, tick it in seek. The playhead is put back afterwards.

Motion Canvas

Scenes are generators that advance a frame per yield, with the view's origin at its centre. playBaked plays baked poses by the scene's own time; centred converts a screen-space pose:

import { useTime } from "@motion-canvas/core";
import { playBaked, centred, motionCanvasReport, byKey } from "romp/motion-canvas";

export default makeScene2D(function* (view) {
  const hero = <Circle key="hero" size={120} fill="#4361EE" />;
  view.add(hero);
  yield* playBaked((t) => {
    const p = centred(poseAtTime(body, t), 1920, 1080);
    hero.position(p.position);
    hero.rotation(p.rotation);
  }, { duration: 6, time: useTime });
});

// the motion check over a project (in the browser, with a Player)
const report = await motionCanvasReport({ seek: (f) => player.playback.seek(f),
  nodes: () => byKey(player.playback.currentScene.getView(), ["hero"]), fps: 30, width: 1920, height: 1080, to: 6 });
